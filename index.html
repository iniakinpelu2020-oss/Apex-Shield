File triage

Hash it, type it, and see what it really is. The file is read here; nothing is uploaded.

Hashes, magic bytes and archive layout are computed in this tab. That is all a browser can honestly do.

Scan it where ClamAV lives

NOT IN A BROWSER

A signature match needs the daily ClamAV database, which is hundreds of megabytes and belongs on a machine with a disk. A browser has neither, so Shield hands you the command instead of inventing a verdict.

clamscan --infected --recursive <path-to-file>

What a hash proves

READ THIS
  • An exact SHA-256 match against a known sample is strong evidence. A hash nobody has seen says nothing about intent.
  • "Clean" from any scanner means "nothing known", never "safe". A freshly built binary is in no database.
  • Compare a second copy by hashing it here: one changed byte changes both hashes completely.

APK static analysis

Permissions, flags and signing scheme straight from the binary manifest. No install, no network, no signature database.

Reads the zip, decodes the compiled AndroidManifest.xml, and looks for v1, v2 and v3 signatures.

Permissions

none yet
  • Drop an APK to see what it asks for.

Dangerous permissions can be misused without the user noticing. Presence alone is not a finding: a torch app needs the camera.

What this cannot tell you

SCOPE
  • Whether the code is malicious. That needs a signature database or a person reading the DEX.
  • Whether the signature is trusted: this reports the scheme and the signer file, not the certificate chain.
  • Whether a store shipped it. Sideloaded and store builds can look identical from the manifest.

Queue and setup

The scan runs on the machine behind your Cloudflare Tunnel. This page is the console in front of it — agree the contract before writing either side.

The contract

DESIGNED 
POST /scan
{ "object": "shield/incoming/<sha256>.apk" }

202 { "id": "<id>", "state": "pending" }

GET /scan/<id>
200 { "state": "pending" | "done",
      "verdict": "clean" | "infected",
      "engine": "clamav 1.4",
      "signatures": "<version and date>",
      "report": "<clamscan output>" }

The Worker never scans. It stores the object reference and the verdict, and the VPS pulls from B2, runs clamscan, and writes the result back.

VPS: ClamAV

NEEDS A MACHINE 
sudo apt install -y clamav
sudo freshclam
clamscan --infected --recursive --log=/var/log/shield.log /srv/shield/incoming

Run the queue worker as a systemd service so a reboot does not silently stop scanning.

URLs: Safe Browsing

FREE KEY NEEDED

Reimplementing URL reputation from scratch would be worse than useless. Google Safe Browsing has a free quota; the key belongs in the Worker's secrets, never in this page.

curl -sS -X POST \
  "https://safebrowsing.googleapis.com/v4/threatMatches:find?key=$SAFE_BROWSING_KEY" \
  -H 'content-type: application/json' \
  -d '{"client":{"clientId":"apex-shield","clientVersion":"1"},
       "threatInfo":{"threatTypes":["MALWARE","SOCIAL_ENGINEERING","UNWANTED_SOFTWARE"],
       "platformTypes":["ANY_PLATFORM"],
       "threatEntryTypes":["URL"],
       "threatEntries":[{"url":"https://example.com"}]}}'
